## 🔴 CAUSA RAÍZ — nombres de propiedad mal escritos en `notion_api.py`

El código escribe/lee propiedades que **no existen** en el esquema real de Notion. La API
devuelve 400 de validación, el `except` genérico lo traga y la función retorna `False` en silencio.
Por eso "guarda" sin error visible y la tabla queda vacía.

### 1. `save_cierre_to_notion()` — línea 250-277 → **rompe la escritura**

| Código manda | Notion espera | Resultado |
|--------------|---------------|-----------|
| `"Nombre"` (title) | **`"Name"`** | ❌ property does not exist |
| `"Energia"` (select) | **`"Energía"`** (con tilde) | ❌ property does not exist |
| `Fecha`, `Completadas`, `Pendientes`, `Notas` | idénticos | ✅ |

Patch exacto:

```python
# línea ~253
"Name": {                                    # antes: "Nombre"
    "title": [{"text": {"content": f"Cierre {fecha}"}}]
},
# línea ~268
"Energía": {                                 # antes: "Energia"
    "type": "select",
    "select": {"name": cierre_data.get("energia", "Media")}
},
```

### 2. `get_cierre_history()` — línea 379 → lee `Energia`, debe ser `Energía`

```python
"energia": props.get("Energía", {}).get("select", {}).get("name", ""),
```

### 3. `get_rueda_vida()` — línea 324 → lee `Area`, el esquema dice **`Área`**

```python
area = props.get("Área", {}).get("select", {}).get("name", "")
```
→ Hoy `area` sale siempre vacío, `rueda` queda `{}` y la función **siempre** cae al fallback
hardcodeado (`Salud: 60, Trabajo: 75, …`). Ojo doble: ese fallback está en escala **0-100** y el
campo `Score` de Notion es **1-10**. Cuando la tabla empiece a tener datos, el dashboard va a
mezclar dos escalas.

**Recomendación adicional:** en los tres `except Exception as e` de esas funciones, loguear
`e.body` además de `e` — con `notion_client.APIResponseError` el detalle del 400 viene ahí, y eso
es lo que faltó para detectar esto en abril.
